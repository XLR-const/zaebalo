ЧАСТЬ 3. ПОДРОБНОЕ ОБЪЯСНЕНИЕ КАЖДОЙ ОШИБКИ
ОШИБКА №1: shuffle=True в train_test_split

Где: models/LightGBM/train_lightgbm.py:38-40

Что неправильно:
python

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.15, shuffle=True
)

Почему это ошибка:

Временной ряд имеет структуру: значение в момент t зависит от t-1, t-2 и т.д. Это причинно-следственная связь.

При shuffle=True данные перемешиваются случайно. Например, исходный порядок:
text

[t1, t2, t3, t4, t5, t6, t7, t8, t9, t10]

После shuffle:
text

[t5, t1, t8, t3, t10, t2, t7, t4, t9, t6]

Теперь при обучении:

    Модель видит t5 раньше t1 — но t5 может быть позже по времени

    Лаги для t1 могут включать t5 (будущее!)

    Модель учится использовать информацию из будущего

Математически:

Правильное обучение: yt=f(yt−1,yt−2,...,yt−k)yt​=f(yt−1​,yt−2​,...,yt−k​)

При shuffle: yt=f(yrandom)yt​=f(yrandom​) — нарушена причинность.

Влияние на метрики:
Сценарий	MAE
С shuffle (как у них)	317 nT
Без shuffle (реальность)	380-450 nT (оценка)

Разница: 30-60% завышение.

Почему они так сделали: Скорее всего, привычка из классического ML, где shuffle нужен. Для временных рядов — нельзя.

ОШИБКА №3: bfill в лаговых признаках

Где: GeoMagAnalyst/app/services/eda.py:158-162

Что неправильно:
python

v_temp = v.ffill().bfill()  # ← bfill использует будущие данные!
df['lag_mean_1h'] = v_temp.rolling(60).mean().shift(1)

Почему это ошибка:

Что происходит при обучении:

    Есть пропуск в данных (NaN)

    bfill() заполняет этот NaN значением из будущего

    Лаг строится на этом заполненном значении

Что происходит в продакшене (инференс):

    Есть реальный пропуск

    Будущих данных нет → bfill() не работает

    Пропуск остаётся NaN или заполняется моделью (другим значением)

    Лаги получаются другими, чем при обучении

Пример:
text

Исходный ряд: [100, NaN, NaN, 200]
После ffill + bfill (при обучении): [100, 100, 100, 200]
Лаг: rolling_mean([100, 100, 100]) = 100

В продакшене (инференс):
NaN заполнен моделью: [100, 150, 175, 200]
Лаг: rolling_mean([100, 150, 175]) = 141.7  ← ДРУГОЕ ЗНАЧЕНИЕ!

Разрыв между train и inference: модель обучена на одних значениях лагов, а в продакшене получает другие.
